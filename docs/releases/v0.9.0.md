# Axern v0.9.0

Axern v0.9.0 establishes the environment execution platform as the complete product boundary and improves local runtime correctness and responsiveness. Deploy matching control, gateway, node, CLI, chart, image, Proto, and SDK builds.

## Platform Boundary

- The supported execution model is `Environment -> Run -> Allocation -> runsc sandbox`.
- Public SDK consumers compose Run and Allocation-scoped Process, File, Archive, declared output, Terminal, SSH, and Tunnel operations without importing repository-internal packages.
- Repository packages and commands outside the environment execution platform boundary are no longer distributed. This is an intentional breaking source-tree change with no compatibility layer.

## Local Runtime And Reliability

- Contributor source Compose and the released CLI-managed local runtime now use distinct Docker Compose projects and state ownership.
- `axern local image load` validates the CLI-managed runtime before pulling or importing an image and reports an actionable initialization error when that runtime does not exist.
- Foreground Run waiting consumes the authoritative Run watch instead of one-second polling, preserving terminal diagnostics while substantially reducing warm local command latency.
- OpenTelemetry and JavaScript dependency updates include the security and maintenance fixes accepted on `main` since v0.8.1.

## Upgrade

Upgrade the Axern control plane, gateway, nodes, CLI, chart, images, Proto artifacts, and SDKs together. Select the context for either the source-managed or released CLI-managed local runtime; each workflow owns and cleans up only its own resources.
