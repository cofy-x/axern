# Axern v0.13.0

This source version adds experimental single-writer Workspaces with independent Namespace-scoped identity, retained byte/inode capacity, managed XFS project quotas and explicit deletion. Runs select one Workspace at `/workspace`. A fresh Run/Allocation can continue using retained files after confirmed cleanup releases the previous writer. Missing or replaced storage remains unavailable; cancellation does not erase data or release retained capacity.

CLI deployment commands separate host serving from development. `axern server` operates the verified native installation through its existing helper; `axern dev` manages Compose development. The `local` command is removed, while its data directories, Compose identity and context remain intact. Workspace CRUD and Run `--workspace` are available through the CLI and Go, Python sync/async and TypeScript SDKs. Workspace-backed execution requires an explicit finite memory limit and cannot request rootfs publication.

Upgrade CLI, SDKs, control, gateway and nodes as one protocol generation. Creation uses `RunControl.AdmitRun` and `NodeLifecycle.AdmitAllocation`; the former creation RPCs are removed so older components cannot ignore a required attachment and create an ephemeral execution. Workspace metadata uses a forward SQL migration that preserves existing control state. Native archive replacement, supported upgrades, backup and replacement-host restore remain outside the experimental installer contract. Do not rebuild a serving database or delete retained directories as an upgrade step.

A source version is not evidence of published binaries, packages, images or native archives. Build and qualify one coherent source revision before use.
