# Axern v0.13.0

This source version adds experimental single-writer Workspaces with independent Namespace-scoped identity, an explicit bound Node, retained byte/inode capacity, managed XFS project quotas and explicit deletion. Runs select one Workspace at `/workspace`. A fresh Run/Allocation can continue using retained files after confirmed runtime and writer cleanup. Readiness requires both `READY` data and no attached Allocation; a terminal Run alone cannot transfer the writer. Missing or replaced storage remains unavailable. Provisioning, cancellation, unavailability and deletion intent retain their capacity charge until explicit deletion is confirmed. Agent tasks, credentials, conversations and coordination remain caller-owned.

Image execution is OCI-only. The Nydus/imagefsd runtime, Rust workspace, daemon APIs and their configuration/build paths are removed. Immutable OCI inputs, local imports, read-only ImageMounts, mount ownership and lease cleanup remain supported. Retained records or images in the removed storage format fail closed; they are not adopted or automatically erased. See [Storage Architecture](../architecture/storage-architecture.md) for the separation between immutable inputs, persistent working files and bounded sealed outputs.

Runtime delivery selects direct `runsc` and its four required helpers from the pinned upstream gVisor archive. Architecture-specific member hashes, sizes, modes and ELF checks bind that profile to exact bytes. Native manifest v3 and the Docker/cache paths share this inventory; the raw upstream archive, containerd shim, checkpoint-gofer and standalone metric-server are not delivered. Build-input provenance, payload integrity, dependency inspection and live runtime qualification provide separate evidence.

CLI deployment commands separate host serving from development. `axern server` operates the verified native installation through its existing helper; `axern dev` manages Compose development. The `local` command is removed, while its data directories, Compose identity and context remain intact. Workspace CRUD and Run `--workspace` are available through the CLI and Go, Python sync/async and TypeScript SDKs. Workspace-backed execution requires an explicit finite memory limit and cannot request rootfs publication.

Build CLI, SDKs, control, gateway and nodes as one protocol generation. Creation uses `RunControl.AdmitRun` and `NodeLifecycle.AdmitAllocation`; the former creation RPCs are removed so older components cannot ignore a required attachment and create an ephemeral execution. Private node publication uses `NodeControl.PublishNodeSnapshot` with the OCI-only inventory contract; the former node-report RPC is removed. Forward SQL migrations add Workspace authority and invalidate only derived node snapshots, preserving existing identity, authorization and execution state. Placement requires a fresh node snapshot from the matching generation.

Runtime Secret files use Allocation-scoped private node storage with verified ownership and file/directory identity. Preparation rejects unsafe or mismatched storage, and cleanup retains unresolved obligations instead of claiming release. Workspace ownership records and cleanup receipts persist independently of in-memory locks; retired generations cannot resume a writer. Public metadata does not expose private host paths or storage identities.

Native lifecycle commands verify their three fixed bootstrap tools against the installed manifest before execution. Staging, lifecycle, qualification and measurement tools load fixed local source modules without reading or writing adjacent bytecode caches. The isolated-Python entrypoints preserve this boundary, and the source stager requires its matching `gvisor_payload.py` sibling.

Managed Linux execution always uses `no_new_privs`. Explicit non-root Exec and PTY requests clear all capability sets before the target program and its environment start, and recheck the requested working directory after dropping privilege. The runsc profile disables setuid privilege gains. Authorized callers retain explicit guest-root preparation. The internal primary entrypoint supports root, non-TTY execution and rejects unsupported metadata instead of silently ignoring a requested identity. Helper injection requires a static Linux executable. Recovery requires both the current process profile and a durable observation of a matching guest Ready response; old or interrupted unconfirmed execution remains unavailable while cleanup authority and Workspace data are retained.

The source and build toolchain uses Go 1.26.10 and Node.js 24.22.2. Agent images use the digest-pinned Python 3.12.16 Debian 13 base, locked pip 26.3 and signed package upgrades, and clear setuid/setgid file bits. Their Node runtime excludes bundled npm, npx and Corepack; callers can add a qualified package manager in a derived image. Dependency updates include the maintained OCI registry client and patched cryptographic and compression libraries. The source security gate audits Go source/test dependency closures, the resolved module graph, the pnpm lockfile, locked Python dependencies and the image pip installer. Verified upstream tool dependencies absent from shipped code are reported separately. Workload SBOM findings require distribution and upstream applicability review; these checks do not establish a zero-vulnerability image. See the [security policy](../../SECURITY.md) for the enforced scope.

The [native Linux installer](../../deploy/standalone/INSTALL.md) remains experimental and supports fresh installation plus its documented systemd lifecycle. Services verify the installation and data filesystem identity before startup; missing or replaced data cannot create an empty replacement installation. Native archive replacement, supported upgrades, backup and replacement-host restore remain outside this contract. Do not rebuild a serving database or delete retained directories as a maintenance step.

A source version is not evidence of published binaries, packages, images or native archives. Build and qualify one coherent source revision before use.
