# Axern v0.12.1

Axern v0.12.1 fixes a node-side startup race in capability reconciliation. An admitted Allocation intent is not eligible for background runtime audits until its immutable launch-enforcement manifest is verified. Reconciliation and fail-stop now share the existing Allocation lifecycle lane with startup and deletion, preventing an early enforcement-loss intent from racing subsequent activation.

A durable termination blocks activation and replay. Missing container metadata alone cannot acknowledge a stopped workload: runtime inventory errors or a surviving runtime retain the termination intent. ExecutionLease expiry rechecks renewals before recording termination. Fail-stop stops the supervised workload while retaining sandboxd, runtime metadata and AllocationState until the control-plane-owned Delete crosses the output-sealing barrier; synchronous startup enforcement and real post-activation fail-stop remain active.

Runtime-audit failures retain a bounded capability key and safe loss or unconfirmed-enforcement diagnosis; post-create verification failures identify the startup phase. Public conditions and terminal messages do not copy raw verifier destinations or runtime paths.

The documentation toolchain pins the patched `fast-uri` 3.1.7 and `undici` 7.29.1 releases for host-parsing and WebSocket decompression fixes. These are not TypeScript SDK runtime dependencies.

Upgrade the CLI, control plane, gateway, tunnel relay, nodes, Helm chart and SDKs together. This patch does not add public APIs or change the Environment, Run and Allocation identities. Create a fresh Run to verify the corrected startup behavior; a previously terminal Run is not revived. The deterministic platform regression is separate from the original consumer cold-start acceptance tracked in [issue #190](https://github.com/cofy-x/axern/issues/190), which remains open pending that acceptance.
