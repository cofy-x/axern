# Axern v0.5.0

Axern v0.5.0 is a coordinated pre-1.0 runtime and resource-contract release.
It makes immutable root filesystems, observed node capabilities, and sandbox
memory enforcement explicit platform invariants while expanding the packaged
agent and service lifecycle surfaces.

## Highlights

- Runtime root filesystems now preserve an immutable lower and separate host
  mount-target projection from guest writable storage. EROFS-backed roots are
  supported through the same source-owned mount identity and lease contract.
- Node capability strings have been replaced by typed, observed capability
  evidence. Placement and node-local admission fail closed when required
  enforcement cannot be demonstrated.
- `memory_bytes` now represents the complete sandbox cgroup budget. Node-local
  control-plane memory is covered by an explicit system reserve, and retiring
  cgroups retain their commitment until cleanup converges.
- Ephemeral storage has an explicit sandbox-lifetime request and hard-limit
  contract for runc writable uppers and runsc file-backed root overlays.
- Claude Code and Codex agent bundles are self-contained and follow a stable
  dual-path mount contract.
- Service deletion is asynchronous and exposes a durable lifecycle instead of
  holding the request open while replicas are reclaimed.
- Release qualification, dependency security, public documentation, and the
  multi-architecture distribution path have been tightened together.

## Upgrade Boundary

v0.5.0 is an incompatible pre-1.0 contract boundary. Mixed v0.4.x and v0.5.0
control-plane or node components are not supported.

The PostgreSQL initial schema and node-local runtime state changed without
compatibility migrations. Before upgrading, drain active sandboxes, preserve
any external data that must survive independently, and rebuild the Axern
database and node-local state. Deploy the control plane and all nodes as one
coordinated version.

Use the v0.5.0 CLI, Helm chart, SDKs, platform images, runtime images, and agent
bundles together. Do not combine v0.5.0 services with v0.4.x generated clients
or persisted development state.

## Verification

- Run the repository release, SDK, open-source, documentation, and build gates
  described in [Release Operations](../operations/releases.md).
- Qualify production node memory reserve values before rollout; the chart does
  not provide a production default.
- Validate both runc and runsc lifecycle correctness for the target deployment
  before publishing the release tags.
