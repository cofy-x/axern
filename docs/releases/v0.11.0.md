# Axern v0.11.0

Axern v0.11.0 adds a bounded external HTTP registry contract to the disposable local runtime. Deploy matching CLI, control, node, gateway, chart, and SDK artifacts; release versions remain coordinated even though this release does not change the public protobuf domain model.

## Local External Registries

- `axern local up --insecure-registry host[:port]` replaces the normalized external HTTP registry allowlist. Omitting the flag preserves the persisted policy; `--clear-insecure-registries` removes it explicitly.
- The policy accepts exact registry hosts only, is bounded to 16 entries, and is applied identically to control-plane resolution and node image pulls. HTTPS remains the default for every unlisted registry.
- The CLI owns the labeled `axern-local-registry` local bridge. A trusted container-only registry can join it under the exact configured hostname; `status` reports the contract and `doctor` detects policy, projection, or network drift.
- External registry containers on that bridge can reach the local control and node containers. Do not use this development-only contract as a shared or production trust boundary.

## Upgrade Boundary

Local runtime state is disposable and version-bound. Reset a pre-v0.11.0 local stack with `axern local reset --force`, start the new release, and configure the intended allowlist explicitly. No compatibility metadata or dual-read path is provided.

## Validation Boundary

Host-safe tests cover policy normalization, fail-closed persistence, idempotent reconfiguration, network ownership, generated Compose configuration, and CLI reporting. Release qualification additionally starts a separate plain-HTTP registry, resolves an exact digest-pinned Environment reference, executes a fresh Run from it, and verifies policy persistence across a local runtime restart.
