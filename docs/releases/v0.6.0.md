# Axern v0.6.0

Axern v0.6.0 adds fail-closed sandbox egress controls and a deliberately
separate DNS-only deny mode across the control plane, node runtime, and Python,
TypeScript, and Go SDKs.

## Network policy modes

- Strict policies are default-deny. Domain grants authorize HTTP/HTTPS on TCP
  80/443 only when controlled DNS, the TTL-bound destination address, and HTTP
  `Host` or TLS SNI all match. Direct IP, alternate DNS, DoT, QUIC, ECH,
  missing SNI, HTTP `CONNECT`, and undeclared protocols remain denied.
- Explicit CIDR rules authorize a canonical IPv4 or IPv6 prefix, TCP or UDP,
  and one or more destination ports or inclusive port ranges. Protected
  loopback, link-local, multicast, unspecified, and cloud metadata addresses
  remain denied. RFC1918 and ULA destinations require an explicit rule.
- DNS deny policies return `REFUSED` for matching conventional UDP/TCP DNS
  names and CNAME chains. They do not block direct IP traffic, DoH, DoT,
  application-owned resolvers, or already-resolved addresses and must not be
  treated as strict egress isolation.

Omitting a policy preserves the unrestricted v0.5.1 behavior. Host networking
conflicts with a policy; isolated networking is normalized to strict deny-all.

## SDK example

```python
from axern_sdk import NetworkPolicy, Sandbox

sandbox = Sandbox(
    client=client,
    image=image,
    network_policy=NetworkPolicy.deny_dns(
        "github.com",
        "*.github.com",
        "githubusercontent.com",
        "*.githubusercontent.com",
        "gitlab.com",
        "*.gitlab.com",
        "bitbucket.org",
        "*.bitbucket.org",
    ),
)
```

Python also provides `NetworkPolicy.strict`, `allow_domains`, `deny_all`,
`CIDRRule`, and `PortRange`. TypeScript exposes the corresponding
`strict`, `allowDomains`, `denyDns`, and `denyAll` methods. Go exposes
`NewStrictNetworkPolicy`, `AllowDomainNetworkPolicy`,
`DenyDNSNetworkPolicy`, and `DenyAllNetworkPolicy`.

## Enforcement and operations

The node-local `egressd` daemon owns policy state and host-side nftables,
TPROXY, DNS forwarding, and bounded HTTP Host/TLS SNI inspection. Axnoded
prepares policy before the workload starts, removes it before interface
release, reconciles persisted allocation attempts on recovery, and fail-stops
policy workloads if required enforcement becomes unavailable.

Both bridge/iptables and bpfnet/eBPF networking retain their existing NAT
ownership. Operators can inspect effective enforcement mode, daemon health,
policy summaries, and failure reasons without logging DNS names, HTTP Hosts,
TLS SNI, or complete policy contents by default.

## Upgrade notes

This is a coordinated control-plane and node-runtime release. Upgrade the
Axern platform as one versioned unit; mixed v0.5.x/v0.6.0 nodes are not a
supported policy-enforcement boundary. Existing workloads without a policy
retain their prior networking behavior.
