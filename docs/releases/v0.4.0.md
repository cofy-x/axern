# Axern v0.4.0

Axern v0.4.0 makes the product CLI the primary installation and execution
surface. A local Axern stack can now be installed and operated without cloning
the source repository or installing the contributor toolchain.

## Highlights

- `axern local up` provisions a version-locked, machine-level local stack from
  assets embedded in the CLI. The local lifecycle now includes status, logs,
  doctor, down, reset, upgrade, and path commands.
- `axern run` is a foreground execution command by default: it streams stdout
  and stderr, waits for a terminal Run state, and returns the workload exit
  code. Detached execution and resumable output remain explicit options.
- Run status and output are durable public API capabilities. Go, Python, and
  TypeScript SDKs expose status watching and cursor-based output reading.
- The default local stack keeps observability optional and pulls workload
  runtime images only when they are first used.
- Release qualification now proves the source-free local path on Linux amd64
  and arm64 before publication and validates the generated Homebrew formula
  against the candidate artifacts.

## Upgrade Boundary

The removed `axern run create` command is not retained as an alias. Use
`axern run --detach` when asynchronous creation is required. Existing local
data is never upgraded implicitly by `axern local up`; run
`axern local upgrade` to perform the explicit backed-up migration.

This remains a pre-1.0 release. Automation should rely on the documented CLI
and public SDK/API surfaces rather than repository scripts or private service
interfaces.
