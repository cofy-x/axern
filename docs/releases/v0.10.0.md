# Axern v0.10.0

Axern v0.10.0 adds immutable rootfs results for successful finite Runs. Deploy matching control, gateway, node, imagemgr, CLI, chart, and SDK builds; the public protobuf and control/node persistence contracts changed together.

## Reusable Rootfs Environments

- A Run can explicitly request rootfs sealing. Its workload status remains the workload result, while a separate `pending`, `ready`, or `failed` finalization result identifies the derived Environment.
- Axnoded streams the stopped workload's runsc writable upper layer while the supervising sandbox still exists and before runtime deletion. Imagemgr validates and bounds it, translates gVisor whiteouts and opaque-directory metadata into OCI layer semantics, combines it with the digest-pinned base, and publishes a content-addressed image to the operator-configured snapshot repository.
- Controld commits the new ordinary Environment, immutable image metadata, Run result, Allocation release, and node acknowledgement through one crash-recoverable lifecycle. There is no separate Snapshot resource or mutable workspace.
- Bind mounts, image mounts, Secret projections, kernel filesystems, processes, sockets, Terminal, SSH, Tunnel, and declared-output retention are excluded. Failed or cancelled workloads publish no Environment.
- The Go, Python, and TypeScript SDKs expose direct Run creation and snapshot waiting; the CLI exposes `--snapshot-rootfs` and `spec.rootfs_snapshot`. The option is deliberately absent from Sandbox helpers because their close path cancels a long-lived Run.

## Operator Action

- Set `plugin.runtime.rootfs_snapshot_repository` on eligible nodes and configure imagemgr registry credentials with pull access to private base images and push access to that repository. Empty configuration keeps the capability unavailable and placement fails closed.
- Snapshot upload is bounded by the Allocation ephemeral-storage limit and a 32 GiB hard ceiling. Repository quota, retention, and unreferenced-blob garbage collection remain operator policy; deleting an Environment removes the Axern reference, not necessarily registry blobs.
- Rebuild pre-1.0 PostgreSQL and node-local state from the current schema before qualification. No compatibility columns, legacy protobuf fields, or dual-read path are provided.

## Validation Boundary

Host-safe tests cover immutable request propagation, capability admission, sealing validation, crash receipts, retry/acknowledgement, SDK wait semantics, and restart preservation. Release qualification must also run the Linux runsc snapshot E2E against a writable registry and prove that two fresh derived Allocations preserve file bytes, modes, ownership, and executable hashes without sharing later mutations.
