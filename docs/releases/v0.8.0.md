# Axern v0.8.0

Axern v0.8.0 is a coordinated breaking release of the public SDK contract. Deploy matching control, gateway, node, CLI, Proto, chart, and SDK builds. Mixed v0.7.x/v0.8.0 components are unsupported, and local databases and node state may be rebuilt instead of migrated.

## Public Contract

- `Environment -> Run -> Allocation -> runsc sandbox` remains the only durable execution chain. `Sandbox` is a thin SDK facade that exposes the Run and Allocation identities.
- A Run may declare up to 16 output paths. axnoded quiesces the Allocation and seals regular files or directory-as-tar outputs before runtime deletion. Per-file, per-tar, and combined limits are 64 MiB, 256 MiB, and 256 MiB.
- The manifest reports available, missing, rejected, capture-failed, or node-unavailable states, plus opaque object identity, size, SHA-256, format, media type, seal time, and expiry. Full SDK downloads verify size and digest.
- Sealed stdout/stderr and declared output are node-local for 15 minutes after cleanup starts. They survive axnoded restart, not Node-disk loss, and are not persistent storage or an object store.

## Breaking Changes

- Public Run, Tunnel, and Sandbox metadata no longer expose Node identity.
- `GatewayControl`, plaintext access-grant routing, Node enrollment/control, lifecycle delivery, operator, network, egress, and relay-control Protocol Buffers are repository-private and absent from released SDK artifacts.
- Python's ordinary `AxernClient` no longer exposes Node administration.
- Unused `lease_ttl_seconds` and `leaseTtlSeconds` options are removed. ExecutionLease remains an internal control-plane/runtime concern.
- TypeScript documentation no longer advertises the removed `execImage`, `processImage`, or `workspaceMount` surface.
- Deleted Proto fields were directly renumbered. No deprecated alias or compatibility shim is provided.

## Process And Cleanup Semantics

- Python unary `exec` bounds collected stdout and stderr at 1 MiB per stream while continuing to drain the RPC; callers use streaming APIs for larger output.
- Python attached-process outgoing requests and TypeScript unread process events have a 64-entry bound. TypeScript applies stream pause/resume backpressure and waits for gRPC write callbacks.
- Closing an attached process attempts `TERM`; explicit kill uses `KILL`. Attached processes have no durable identity, and durable workload termination remains Run cancellation.
- Sandbox close reports cleanup failures and does not claim terminal completion. Callers that require durable confirmation explicitly wait for the Run terminal state.

## Migration

1. Upgrade all components and SDKs together and recreate unsupported old state.
2. Remove client references to Node IDs, Node targets, private generated packages, NodeAdmin, and lease TTL options.
3. Persist public Run and Allocation IDs for recovery.
4. Declare result paths before Run creation; after terminal status, fetch the manifest and copy verified bytes to caller-owned durable storage before expiry.
5. Use a new Run/Allocation when an operation requires an independent writable filesystem.

Availability is determined by the completed GitHub Release and registry publication, not by source metadata alone.
